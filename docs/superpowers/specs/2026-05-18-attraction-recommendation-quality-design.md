# 景点推荐质量优化设计

## 背景

当前项目已经通过高德 `amap-mcp-server` 获取 POI，并用 `AttractionSearchAgent` 生成搜索关键词。现有问题集中在景点候选质量：当搜索词偏泛时，结果容易出现“城市公园、历史街区、特色街区、观景台”等模板化地点，用户会觉得推荐不够具体、不够像真实旅行建议。

本次优化只聚焦景点候选质量，不重构完整行程规划器，也不更换前端交互。

## 目标

- 优先推荐真实、可独立游览、能在地图中定位的景点、街区、场馆或景区。
- 明显降低泛词地点、子 POI、配套设施和低相关 POI 的出现概率。
- 保留现有高德 MCP 接入方式，先用确定性评分层提升质量。
- 支持后续接入 Google Places、Foursquare 等增强数据源，而不影响当前高德实现。

## 非目标

- 不在本阶段启用完整 LLM 行程规划。
- 不在本阶段新增前端页面或复杂筛选控件。
- 不在本阶段引入必须付费的新地图服务。

## 推荐方案

新增 `AttractionRecommendationService`，放在后端服务层，位于 `AttractionSearchAgent` 和 `AmapMCPClient` 之间或紧贴 `AmapMCPClient` 输出之后。

职责划分：

- `AttractionSearchAgent`：继续生成具体 POI 搜索词。
- `AmapMCPClient`：继续通过 `maps_text_search` / `maps_search_detail` 获取原始 POI。
- `AttractionRecommendationService`：负责清洗、去重、打分、排序和截断候选景点。
- `PlannerAgent`：继续消费已筛选后的景点列表。

## 数据流

1. 用户提交自然语言旅行需求。
2. `TravelRequirementParser` 解析城市、天数、偏好、必去和避开地点。
3. `AttractionSearchAgent` 生成 8-12 个具体搜索词。
4. `AmapMCPClient` 使用高德 MCP 拉取候选 POI 和详情。
5. `AttractionRecommendationService` 对候选做质量评分。
6. 返回 `days * 3` 个高质量景点给规划器。

## 评分规则

每个候选景点计算一个 `recommendation_score`，内部使用即可，不需要立刻暴露到前端。

加分项：

- 名称或类别匹配用户偏好。
- 类别属于博物馆、展览馆、风景名胜、旅游景点、古镇、古村、故居、遗址、公园、地标、历史街区等真实游览对象。
- 出现在用户 `must_visit` 中。
- POI 详情中存在评分，且评分较高。
- 地址、坐标、名称完整。

扣分项：

- 名称是模板化泛词，例如“城市公园”“特色街区”“历史文化景点”“观景台”“美食街”等。
- 属于酒店、民宿、停车场、地铁站、公交站、厕所、办公室、售票处、游客中心、服务中心、入口、出口等配套设施。
- 看起来像馆内子 POI 或大景区内部小点位。
- 命中用户 `avoid_places`。
- 与已选候选重复或高度近似。

排序策略：

- 先按硬过滤移除明显不合格候选。
- 再按评分排序。
- 最后做轻量地理分散，避免全部落在同一小片区，但地理分散不能覆盖质量排序。

## MCP 策略

第一阶段继续使用现有高德 MCP：

```json
["uvx", "amap-mcp-server"]
```

原因：

- 项目已经集成并有测试覆盖。
- 对国内城市 POI 覆盖更合适。
- 不增加新的 API Key 和成本。

后续可以通过统一接口扩展其他 MCP：

- Google Places MCP：适合国际城市、照片、营业时间和更丰富地点详情。
- Foursquare Places MCP：适合热度、餐饮、街区体验类补充。

本阶段只预留抽象边界，不实际接入新 MCP。

## 错误处理

- 高德 MCP 不可用时，继续使用本地 fallback 景点数据。
- 候选评分后不足时，允许从本地种子数据补齐。
- 如果所有候选都被过滤，回退到当前 `_fallback_attractions_for_city` 的稳定结果，保证接口始终可用。

## 测试计划

新增或调整后端测试：

- 泛搜索词不会返回“城市公园”“特色街区”“历史文化景点”等模板地点。
- 酒店、停车场、游客中心、入口、厕所等非景点被过滤。
- `must_visit` 景点优先出现在结果中。
- `avoid_places` 景点不会出现在结果中。
- 同一大景区的入口、服务点、馆内小点位不会挤掉独立景点。
- 高评分、强偏好匹配景点优先于低相关候选。
- MCP 不可用时 fallback 仍返回稳定结果。

## 验收标准

- 以“广州 3 天 历史文化”为例，优先出现陈家祠、沙面岛、南越王博物院、越秀公园等真实地点，而不是“广州历史街区”“广州城市公园”。
- 以“珠海 3 天 历史文化”为例，优先出现珠海博物馆、唐家古镇、梅溪牌坊等真实地点。
- 现有后端测试继续通过。
- 前端无需改动即可消费优化后的景点列表。
